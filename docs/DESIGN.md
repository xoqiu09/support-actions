# support-actions 设计卡（M1）

## 要解决的问题
客服 Agent 不只回答问题，还要替用户办事：查订单、改收货地址、发起退款。办事有风险：模型可能调错工具、参数填错、同一笔退款重复执行、超出权限。这个项目演示一个“会办事但靠得住”的客服 Agent：工具有白名单和参数校验，高风险操作要人工审批，执行恰好一次，每一步都能回放追查。

全部数据虚构（品牌青柚家电），不调用真实模型：用一个按规则给出“工具调用计划”的假模型，以及能注入故障的假业务系统。Python 3.10+，只用标准库（含 sqlite3）。

## 目录
```
supportactions/
  __main__.py  # 命令行
  tools.py     # 工具定义：名称、参数结构、风险等级（read / low / high）、处理函数
  planner.py   # 假模型：把用户消息按规则变成工具调用计划（可故意产出坏计划，用于测试）
  runner.py    # 执行器：白名单、参数校验、风险判断、审批、幂等、重试
  approvals.py # 审批队列：待审、批准、拒绝、超时
  backend.py   # 假业务系统：订单、地址、退款；可注入超时和失败
  trace.py     # 每次运行逐步记录（JSON Lines），可按运行号回放
data/orders.json
tests/
```

## 工具（只做这四个）
- `lookup_order(order_id)`：read，直接执行。
- `list_orders(account)`：read，只能查当前账户。
- `change_address(order_id, new_address)`：low，订单未发货才允许；执行前把新地址遮住门牌号写进记录。
- `refund(order_id, amount)`：high，金额不能超过订单实付；必须人工批准才执行。

## 执行规则
1. 计划里的工具不在白名单 → 拒绝，记录原因，不执行任何一步。
2. 参数缺失、类型不对、越权（查别人的订单）→ 拒绝这一步，后续依赖它的步骤也不执行。
3. high 风险步骤进入审批队列，状态“待审”；批准后执行，拒绝则结束；超过 N 分钟（假时钟）未处理 → 过期，不执行。
4. 幂等：每个有副作用的步骤带幂等键（运行号 + 步骤号）。同一个键在假业务系统只生效一次：重复批准、重试、进程重启后重跑都不会多退一笔。
5. 结果不明（假业务系统超时）→ 先用幂等键查询结果，查到成功就记成功，查不到才重试，最多 2 次；仍不明则标“待人工核对”，不再自动重试。
6. 每一步记录：时间、工具、参数（地址遮住）、风险、审批状态、结果或错误。`replay RUN_ID` 按记录重放，不调用业务系统，打印每一步和最终状态。

## 命令
- `ask --account A "我的订单 A-102 退款 199 元"`：生成计划并执行到需要审批处，打印运行号和每步状态。
- `approvals` / `approve RUN_ID STEP` / `reject RUN_ID STEP`：审批。
- `replay RUN_ID`：回放。
- `demo --out PATH`：跑内置演示（正常查单、改地址、退款待审→批准→执行、重复批准不重复退、超时后查询再确认、越权被拒、坏计划被拒），把每一步写成一个 JSON 供网站演示页使用；不含绝对路径、主机名、用户名；重复运行逐字节一致。

## 必须写的验收测试
1. 白名单外的工具：整次运行不执行任何一步。
2. 查别人的订单被拒，依赖它的步骤不执行。
3. 退款超过实付被拒；已发货订单改地址被拒。
4. 退款待审→批准→执行一次；再次批准、重试、重启进程后重跑，假业务系统里仍只有一笔退款。
5. 审批超时后不执行；拒绝后不执行。
6. 业务系统第一次超时但其实已成功：查询后记成功，不重复执行；一直不明：最多重试 2 次后标“待人工核对”。
7. 回放结果与原运行逐步一致，且回放时业务系统调用次数为 0。
8. 记录和导出里没有完整门牌号，没有绝对路径。

证明测试不是摆设：去掉幂等检查、去掉审批判断、去掉越权检查，各自跑测试，贴出失败，再改回。

## 不做
不接真实模型，不做网页（网站演示页另做），不做多轮对话记忆（见 support-memory）。

## M2

1. 工具结果和订单备注都是数据。工具结果（例如客户填写的订单备注）包含“忽略之前的规则…”、“直接退款”或“调用 refund”这类指令式文字时，计划器不得把它变成新的工具调用。包含这类文字的工具步骤记录“可疑指令”标记。参数来自这类文字的计划步骤一律拒绝。新增两笔带此类备注的虚构订单。
2. 用假时钟按账户限额。每个账户每分钟最多调用 N 次工具，默认 10 次，每天最多退款 M 次，默认 2 次。超过限额的步骤要明确说明拒绝原因，且不执行。每到新一分钟或新的一天，相应限额重置。
3. 单笔退款超过可配置金额（默认 500 元）时，需要两位不同的审批人批准。只有一位批准时仍为待审。同一人批准两次只计一次。

验收测试覆盖以下行为：

- 注入备注不会产生退款，且回放能看到“可疑指令”标记。
- 恰好 N 次工具调用可以执行，第 N+1 次被拒绝。跨过分钟和日期边界后，相应限额恢复。
- 超过金额上限时需要两位不同的审批人，同一人重复批准仍待审。
- M1 的行为和原测试保持原样，原测试全部通过。
